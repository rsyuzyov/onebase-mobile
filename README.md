# onebase-android

Обёртка, которая позволяет запускать платформу [onebase](https://github.com/ivanarama/onebase)
на Android: APK со встроенным кросс-собранным Go-бинарём платформы, локальная база SQLite
и WebView поверх штатного лаунчера информационных баз.

Практическая цель — заменить мобильную платформу 1С в складском приложении: работа
автономно на терминале сбора данных, сканирование штрихкодов, обмен с центральной базой.

## Принципы

1. **Платформа берётся из апстрима и не форкается.** Этот репозиторий содержит только
   обёртку. Если чего-то не хватает в самой платформе — обсуждение с автором и PR в апстрим,
   а не своя ветка. Всё, что закрывается снаружи (переменные окружения, флаги, обёртка),
   закрывается снаружи.
2. **Баз может быть несколько.** Добавление, изменение и удаление баз — штатным лаунчером
   onebase, своего механизма не заводим.

## Как это устроено

```
APK
├── jniLibs/<abi>/libonebase.so   ← кросс-собранный бинарь платформы
├── assets/project/                ← конфигурация (для первой базы)
└── Kotlin
    ├── ForegroundService → onebase start --no-gui, HOME=<filesDir>
    └── MainActivity      → WebView на адрес из stdout лаунчера
```

Ключевые точки, проверенные на платформе:

- бинарь кладётся как `lib*.so` в `jniLibs` и включается `useLegacyPackaging = true` —
  с Android 10+ исполнять файлы можно только из `nativeLibraryDir`;
- `onebase start --no-gui` не открывает GUI и печатает строку
  `Лаунчер доступен по адресу: http://127.0.0.1:<порт>/...` — отсюда обёртка берёт адрес
  для WebView (порт динамический);
- реестр баз лежит в `$HOME/.onebase/ibases.yaml`, поэтому процесс запускается
  с `HOME=<filesDir приложения>`;
- базы лаунчер поднимает дочерними процессами того же бинаря;
- сканер штрихкодов в режиме keyboard wedge попадает прямо в поле формы и нативного кода
  не требует.

## Сборка бинаря платформы

```
GOOS=android GOARCH=arm64 CGO_ENABLED=0 go build -ldflags "-s -w" \
    -o app/src/main/jniLibs/arm64-v8a/libonebase.so ./cmd/onebase
```

Для 32-битных устройств и для эмулятора x86_64 нужен NDK: там `GOOS=android` требует
внешней (cgo) линковки.
