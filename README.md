# onebase-mobile

Мобильное приложение для платформы [onebase](https://github.com/ivanarama/onebase):
APK со встроенным кросс-собранным Go-бинарём платформы, локальная база SQLite и WebView
поверх штатного лаунчера информационных баз. Телефон работает автономно — сервер не нужен.

Практическая цель — заменить мобильную платформу 1С в складском приложении: работа
без сети, сканирование кодов маркировки, обмен с центральной базой.

## Принципы

1. **Платформа берётся из апстрима и не форкается.** Этот репозиторий содержит только
   обёртку. Если чего-то не хватает в самой платформе — обсуждение с автором и PR в апстрим,
   а не своя ветка. Всё, что закрывается снаружи (переменные окружения, флаги, обёртка),
   закрывается снаружи.
2. **Баз может быть несколько.** Добавление, изменение и удаление баз — штатным лаунчером
   onebase, своего механизма не заводим.

## Как это устроено

```
APK
├── jniLibs/<abi>/libonebase.so   ← кросс-собранный бинарь платформы
├── assets/project/                ← демонстрационная конфигурация склада
└── Kotlin
    ├── OneBaseService → onebase start --no-gui, HOME=<filesDir>
    ├── MainActivity   → WebView на адрес из stdout лаунчера
    ├── ScannerFrame   → штрихкоды до метода ввода
    └── Diagnostics    → падения и журнал на диск
```

Ключевые точки, проверенные на устройстве:

- бинарь кладётся как `lib*.so` в `jniLibs` и включается `useLegacyPackaging = true` —
  с Android 10+ исполнять файлы можно только из `nativeLibraryDir`;
- `onebase start --no-gui` не открывает GUI и печатает строку
  `Лаунчер доступен по адресу: http://127.0.0.1:<порт>/...` — отсюда обёртка берёт адрес
  для WebView (порт динамический);
- реестр баз лежит в `$HOME/.onebase/ibases.yaml`, поэтому процесс запускается
  с `HOME=<filesDir приложения>`;
- базы лаунчер поднимает дочерними процессами того же бинаря;
- лаунчер открывает выбранную базу через `window.open`, поэтому WebView нужны
  `setSupportMultipleWindows(true)` и `onCreateWindow`, схлопывающий второе окно
  в текущий экран.

## Сканер штрихкодов

Наивное ожидание «keyboard wedge попадёт прямо в поле формы» не оправдалось: на Android
аппаратный ввод проходит через экранную клавиатуру, и она подставляет символы своей
раскладки. Серийный номер кода маркировки `5ObkkJ93igjJ` приезжает как `5ЩиллО93шпоО`,
а системная настройка раскладки для устройства не помогает — метод ввода применяет свою
поверх неё.

Поэтому нажатия читаются **до метода ввода**, в `dispatchKeyEventPreIme` на корне экрана:

- у самого WebView перехватывать бесполезно — ввод обрабатывает его внутренняя вьюха;
- цепочка «до метода ввода» идёт только по вью с фокусом, поэтому WebView его запрашивает;
- разделитель групп GS (`0x1D`) сканер шлёт как F8 — клавиши для него не существует;
  без распознавания код маркировки склеивается в одну строку и на группы не разбирается;
- кириллица и иероглифы приходят без `unicodeChar` и отдаются методу ввода: он умеет то,
  чего не умеет раскладка.

Собранный код вставляется в активное поле и рассылается событием `ob-scan`, чтобы
интерфейс мог принимать сканы и без фокуса в поле.

## Диагностика

У пользователя склада не будет ни отладчика, ни удалённого доступа к телефону, а кнопки
«сообщить о проблеме» недостаточно: при падении на старте отправлять уже некому. Поэтому
перехватчик падений ставится в `Application` (ловит и сбои до появления интерфейса), а
отчёт и журнал событий пишутся на диск сразу и переживают смерть процесса. При следующем
запуске приложение предлагает отправить отчёт.

## Сборка

```
GOOS=android GOARCH=arm64 CGO_ENABLED=0 go build -ldflags "-s -w" \
    -o app/src/main/jniLibs/arm64-v8a/libonebase.so ./cmd/onebase
```

Для 32-битных устройств и для эмулятора x86_64 нужен NDK: там `GOOS=android` требует
внешней (cgo) линковки.

⚠️ На **x86_64 платформа не запускается**: SQLite падает с `SIGSYS`, потому что
`modernc.org/libc` зовёт legacy-syscall `lstat`, запрещённый seccomp-фильтром Android.
На arm64 барьера нет. Чинится в `modernc.org/libc`, не в onebase.

## Проверки

```
./check.sh
```

Модульные тесты, статический анализ и инструментальные тесты на подключённом устройстве
или эмуляторе. Инструментальные идут против поддельного сервера, а не против бинаря
платформы, поэтому работают и на x86_64-эмуляторе, где сама платформа не стартует.

## Состояние

Работающий прототип: установка, миграция, лаунчер, работа в интерфейсе, проведение
документов, сканирование кодов маркировки, обмен с центральной базой, автономность.
